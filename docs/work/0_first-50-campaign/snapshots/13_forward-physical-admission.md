## Physical observation and estimator separation

`generate-physical.mjs` generates six original observations: native, horizontal/vertical/combined mirrors, an isolated symmetric part, and a cap-only erased image. It uses the already-reviewed ray/halfspace generator with constant neutral tones by physical surface class. The known asymmetric 6/4/2 shape exists in the native raster as a long flat extension, four studs, and a short extension. The estimator receives that entire physical model and RGBA; it receives no observed core order, camera, face labels, feature owners, search center, or generator record. The isolated symmetric model removes both extensions and retains the real proper 180-degree symmetry.

The finite generator model contains three boxes and four regular 32-sided solid prisms. Ray visibility is physical nearest-entry visibility through each convex solid. The independent estimator builds faces from the same public primitive declarations, projects polygons and draws the visible faces through a depth buffer. It does not import the generator or its camera implementation. Generator cameras use cross products; estimator cameras use explicit projection columns. Shared model constants describe the physical objects and neutral per-surface-class tone contract, not per-instance answers or per-pixel nuisance textures.

The estimator is a separate entry point/process. Its core imports only `surface-raster.mjs`, which imports nothing. Its CLI imports `study-io.mjs`, which has exactly `node:fs`, `node:path`, `node:url` and `node:crypto`. Global `performance.now()` and `process.memoryUsage()` supply cooperative resource checks. It never opens any private-truth or private-owner file and accepts no truth argument. Functional output is `estimate.json`; elapsed/RSS measurements live separately in `telemetry.json` so deterministic output can be byte-compared across processes.

## What the finite measurement proves

`public-camera-grid.json` contains a uniform full-circle 15-degree azimuth grid, both signs of elevation at absolute values 15/30/45/60/75 degrees, both up signs, and scales 1/2/3 pixels per document unit. This is 1,440 camera cells. All integer image translations for which the model is fully visible form the translation universe. The chosen true pose is not provided to the estimator and the grid is not narrowed around it.

Feasibility uses one explicit symmetric relation: each source tone sample has that same tone somewhere in a 3 by 3 neighborhood of the prediction and vice versa. Every foreground pixel and all background pixels participate. This relation bounds per-tone sample-center displacement by `sqrt(2) < 1.5` pixels. It is a declared synthetic allowance, not a proof that arbitrary source art or antialiasing lies within 1.5 pixels. Pixel-midpoint edges between adjacent different-tone samples locate some class transition along that sample segment within 0.5 pixel; they do not alone identify the physical owner or a continuous point correspondence.

If a translated model satisfies the relation, each extremal foreground coordinate must lie within one integer pixel of the observation's matching extremum. Intersecting the minimum and maximum coordinate conditions leaves at most three X and three Y translations per camera. Thus no feasible integer translation is removed by this particular necessary bbox bound, and at most 1,440 + 12,960 = 14,400 camera/translation cells need consideration. This does not cover fractional translations. Candidate rasters are complete finite projected surfaces; an out-of-frame foreground is refused instead of clipped.

Every surviving camera/translation is retained, regardless of residual rank. No best-loss tie-break creates uniqueness. For observed top/wall and wall/body-top tone edges, the estimator asks every surviving model which physical stud can own the edge within the same neighborhood allowance. An edge is retained as owned only if every model gives exactly one identical physical owner. For each of four owners it retains all consistent top/base edge supports and every pixel-compatible pair under the reported projected height. It reports signed intervals expanded by 3 pixels for the pair. These remain finite-model pixel-compatible rim claims, not continuous point correspondences or source-authoritative owners.

The independent judge reads the generator's private owner image only after the estimate exists. It checks every reported cap/wall sample against the physical owner in that private image, checks whether the true finite pose survived, and requires all four signed groups for the positive/mirror cases. The symmetric case must retain at least two poses and refuse fixed-owner claims. The erased full-model case must refuse owned wall rims. Its empty finite feasible set cannot replace the exact cap-only ambiguity proof, because the physical model in the census still includes the removed body and walls.

## Bounds and failure behavior

The estimator checks 60 seconds per case and 16,384 camera/translation cells. Exhaustion gives `search-incomplete`, retaining its partial feasible list without a uniqueness claim. It caps a candidate raster at 1,000,000 pixels, observed target rim edges at 20,000 and pair checks at 200,000. Memory arrays are bounded by those fixed dimensions; sampled RSS exceeding 256 MiB refuses. The memory check is cooperative observed RSS, not an OS-enforced private-memory ceiling. Existing runtime overhead and garbage-collection behavior must be reported; they are not silently called proven private-memory bounds.

No executed measurement exists for this packet yet. Camera counting, PNG/source closure, ray/candidate raster agreement, owned supports, predicted coordinates, runtime, and truth independence must be measured. A complete finite success would still leave off-grid cameras, fractional translations, antialiasing, drawing-model uncertainty, and continuous global exclusion unresolved. It supplies no native qualification or opaque camera capability and does not satisfy the frozen 12-site source-lattice gate by relabeling four studs.
