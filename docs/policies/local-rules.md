# Local rules

This repository's own rules, read at session start with [`docs/START.md`](../START.md). They add to the fleet canon in `AGENTS.md` and never override it. Each rule added on 2026-09-22 states its reason in one clause.

## The booklet and the reference

- The booklet is the product's input, not a held-out test set (owner, 2026-09-22). Any session may read any page, and `npm run verify`, browser suite included, runs in full whenever it is due. The blind, staged first-50 protocol (source admission, holdout staging, the ban on the full browser gate before a late stage, frozen one-shot contracts) is retired, because it produced no product commit after 08-29 and no record shows it catching a defect; its last working state is branch `archive/first50-campaign-wip-20260908` (f44f1b8).
- The official LEGO Builder model in ignored `output/official-model/` is a private reference, never committed. Target rule: it is the per-step scoring reference a rebuild is scored against, and it may be played back as a reference build only under a label saying so, because a per-step score against the real answer is what this work is measured by. `npm run booklet` (`tools/booklet/`) scores reading, alignment, catalog coverage and reference playback per step against it; camera-fit and placement scoring are not built yet, and `compareBuilds` still runs only against a synthetic reference (`apps/web/e2e/build-search.spec.ts`). The experimental real-build family (`apps/web/e2e/real-build-*.ts`, e.g. `real-build-action-ledger-compile.ts`, which reads the model to bind printed steps to it) still reads the official model directly as a named exception, retired only with that family.
- Product code (the booklet reader, placement search and its in-loop scoring, anything that writes a document) never imports or reads the official model; only evaluation, reference playback and their tests may, because a builder that can see the answer proves nothing about reading the booklet. An `eslint.config.js` rule enforces this for `packages/*/src` and `apps/*/src`: they may not import `tools/booklet`, whose `answer-key/` reads the model, or name `output/official-model`. A path assembled at run time is beyond a linter; `tools/booklet/answer-key-guard.test.ts` lints each banned construct through the real config.
- Log every selection attempt (each run scored against the reference to choose a method, threshold, prompt or setting) under `output/`, and report the attempt count with any score it produced, because a best-of-N score without N cannot be told from a lucky draw.
- Claim that a method generalises only from steps it was not tuned on (later steps of this booklet, or another booklet), because a score on the tuning steps measures the tuning.
- An individual model question still never carries its answer (no element id, part name or official-model fact), because a judge told the answer is not being asked anything.
- pdf.js (`pdfjs-dist` at the version `package-lock.json` pins) is the rasterizer of record for booklet pages, and the byte-exact Poppler roster is retired to branch `archive/first50-campaign-wip-20260908` (f44f1b8), because one lockfile-pinned rasterizer reproduces page pixels with no second toolchain to restore.
- Inspect panel N+1 before accepting printed step N, as the minimum lookahead, not proof: if it hides the disputed part or face, go on to the first later panel that shows it, else record `not-observable`. A usable highlight or exploded-ghost comparison may settle step N on its own panel, but a later panel's disagreement triggers backtracking. Keep every rejected alternative and report the reversal count and deepest reversal depth.
- A printed step's panel difference is a prior over about a stud's neighbourhood, not an offset: the top-scoring silhouette offsets landed 0.57, 0.60 and 2.50 studs from the red arrows, whose own offsets ranked 43rd, 82nd and 271st, because about seventy candidates sit within a stud of any point (stud pitch 40 px, plate height 13). Report the winner's distance from the answer, never its rank. The pairs a difference can honestly be read from and the steps that need one do not intersect, so carry registration quality as a per-pair fact and fall back when it is poor.

## Looking

- Look at every picture: open the source before reasoning, render the candidate, inspect both, and treat a score as a lossy summary when it disagrees with the pixels. New or changed render geometry gets matched top, bottom, front, back, left, right, isometric and underside-oblique source-versus-catalog views, plus interior or cutaway views a cavity needs; a surface no source image shows is `not-observable`, never certified exact. Packet generation cannot approve itself: name every inspected image and publish a separately bound `same`, `different` or `not-observable` outcome.
- Inspect at native resolution: a composite for inspecting a rendered part must reproduce the packet PNG pixels without resampling and name the raw files it bound. A helper's `thumbnail((320, 320))` once showed every 640x640 image at half linear resolution inside a 2560x724 sheet, and 24 immutable sidecars recorded that as original-resolution review; scale erases one-pixel seams, hard-edge shading, thin cavities and winding defects. Keep invalid sidecars as counterevidence and capture a fresh batch instead of overwriting.
- Do the task through the app's own UI and look: drive the served app, click the real controls, capture real screenshots. Source or hook presence approves nothing, nor does one flattering screenshot: capture the canonical isometric and orthographic views, read `window.render_app_to_text()`, `capture_model_views()`, `get_model_snapshot()`, `advanceTime(ms)` and the validator output beside them, and confirm pixels, structured state and intended behaviour agree. Looking caught studded tiles, an empty scene framed inside the first brick and a palette overflowing under the canvas, each with tests passing (2026-07-31).
- Look at a worktree's change in the editor served from that worktree (`npx vite --port <free port>` in its `apps/web`), because the desktop preview's launch configuration serves the main checkout: on 2026-09-24 it ran catalog `/31` and refused a `/32` reference build with `Connection connection-844 is not uniquely inferred`.
- The editor persists its project (`indexeddb-project-repository.ts`), so `page.goto` is not a fresh plate and clearing `localStorage` does not reset it. Give each independent UI assertion its own browser context, or clear state through the app's controls: five parts driven through one page came back as one part and one hash, while a context per part gave five distinct hashes with zero blocking issues each.
- Label image ground truth at more than one zoom before committing it: region `p200-r0` read as a plain diagonal at scale 4 and arcs over every stud at scale 6, and the wrong label would have scored a correct measurement as a false positive. `apps/web/src/instructions/__fixtures__/booklet-edges.json` keeps both scales of every edge.
- The interactive camera is not the capture camera: `createCanonicalViewPacket` frames an empty document with a half-unit box, which in a viewport put the camera inside the first brick. `BrickViewport` frames at `Math.max(view.frameRadius, GRID_SCENE_RADIUS)` with near and far from `orbitCameraFrustum` at the live orbit distance. The frustum half is gated in `packages/rendering/src/rendering.test.ts`; the framing minimum is not, since `GRID_SCENE_RADIUS` is private to a `.tsx` component, and exporting it and pinning it against one part's frame radius would be its gate.

## Models and subagents

- From product or harness code, only cropped callout thumbnails and step panels from the user's own booklet may go to a model, for part identification or printed-step placement description; a session reading a full page for its own inspection is not a model call and is covered by [The booklet and the reference](#the-booklet-and-the-reference) instead. Never send a whole booklet, other repository content, credentials or any other user reference, and keep responses only as local ignored evidence.
- Ask models closed questions: two pictures side by side at one height, same part or not, nothing else on screen, the answer withheld, room for "unsure", and escalation from contact sheets to single-pair renders. Two raters on different models agreed 84 of 84 that way, including all eight "different" calls and both unjudgeable pairs, with "unsure" used twice and correctly. An open pick-one-of-N question with free text and a confidence kept 273 answers from 285 drawings but agreed with itself on only 138 of 265 checkable descriptions (52.1%), and its confidence barely separated them (mean `0.892061` on kept answers, `0.877480` on contradicted ones), so it cannot gate admission. Agreement is not correctness, but a poor vision result is first checked for an answerable question and a grader measuring sight, not vocabulary.
- Reading a part in isolation differs from reading it in a scene, and the picture is worth more than the prompt: in the vision benchmark once kept at `output/vision-benchmark.json`, one model answered 6 of 6 assembly crops at 0.35–0.58 confidence with at least one plainly wrong, yet scored 28/28 on stud dimensions from the booklet's isolated inventory thumbnails, and 27/28 with a naive control prompt. The misses left were taxonomy gaps (no answer for an arch or a modified brick), not misread shapes. Labels are element ids paired from the text layer by `apps/web/src/instructions/parts-inventory.ts` against Brickset's inventory for set 21066.
- Per-image vision classification is a minimal-context one-shot model call (one image, one closed question, no repository context), never a full agent session, because 369 such sessions of about 10 calls each were 15.8% of spend by price (measured 2026-09-22 from session transcripts; see `docs/work/1_booklet-reset/design.md`).
- Read-only lookups (find a file, a symbol, a doc passage) go to the `scout` agent type in `.claude/agents/scout.md`, which has search and read tools only, a smaller model and low effort, because subagents and workflows took 66% of this repo's tokens, all at max effort (measured 2026-09-22 from session transcripts; see `docs/work/1_booklet-reset/design.md`).

## Review, devlog and docs

- Independent review is sized to risk, not commit count: an ordinary milestone still merges as soon as its gates are green (fleet canon R6), but a milestone that is substantial, crosses a trust boundary, claims a measurement, or touches concurrency, money, a dependency (supply chain) or a sibling repo gets independent review before it merges, plus a focused re-review whenever a later fix invalidates the round before it (fleet canon). Mechanics are in `../fleet/docs/skills/multi-cli-review.md`, and every review prompt carries this repo's doc-accuracy addendum: check that docs in the diff match the implementation and flag stale ones. Trust-broker, evaluator, provider, consent, signing, persistence, scoped-patch, migration, recursive-loop and data-loss changes add a security or multi-model review, and a trust-boundary change adds a repository-grounded threat model (the `security-threat-model` and `security-best-practices` skills).
- A `docs/devlog/summary.md` line is at most 300 characters (the date, what moved, what it cost; newest first), with the rest in `docs/devlog/detailed/`, because at 9bdf450 76 of its 112 lines ran past 300 characters, the longest 4,763, and it stopped working as an index. It is history and `docs/design/building-system.md` is the position; neither stands in for the other.
- Keep `README.md` and the design docs true to what is implemented.

## Parts, sources and licences

- User-provided and publicly reachable construction sources are authorized inputs for this repository's private, noncommercial reconstruction and evaluation work, and commercial-rights review must not block that work. Keep native payloads local when practical, preserve exact identities and hashes, never describe upstream material as project-owned, and never broaden this authorization to public redistribution or training.
- Record every code, geometry, connector, collision, weight, model and example source in `docs/dependency-data-bom.md` with its source, version, licence, attribution, redistribution and training rights and allowed role, and keep file-level LDraw provenance; permission to reuse geometry never implies permission to train.
- Bundle real LDraw geometry as the render layer with per-file authorship and licence preserved; the BOM and generated notices describe it as bundled under CC BY 4.0 from the first admission that bundles a file. Reuse is not training, and a generated approximation is no substitute where lost fidelity changes booklet-panel measurement.
- Licence uncertainty must not block private, noncommercial reconstruction: a CC BY-SA source such as the LDCad Shadow Library may supply catalog truth. Its attribution travels with the derived data and is rendered into `docs/bundled-geometry-notices.md`, `docs/dependency-data-bom.md` records that ShareAlike would attach on redistribution, no source file or excerpt enters Git, and training rights stay unheld.
- A part the catalog lacks is a work item, not a blocker: add it rather than substituting or dropping the shape. It carries its family, real LDraw identifier, connectors, collision primitives and provenance, and the palette keeps it findable: grouped by family, searchable by name, size and identifier, previewed from its own geometry. Adding it is a catalog-truth change: bump `BUILTIN_CATALOG_VERSION`, extend `MIGRATABLE_CATALOG_VERSIONS`, and let the migration report say what changed (2026-07-30; steps in `docs/design/part-model.md` § Admission checklist).
- Advance catalog, collision and validator truth versions at the first production part admission rather than at contract change, and keep the preceding version as a historical migration snapshot so existing documents keep their interpretation and hashes.
- A part whose source frame is not centred carries an explicit source-to-catalog frame in its declaration, not a repair through connector seat planes or per-call-site offsets.
- Part geometry is a lookup, not a judgement call: before authoring a part from memory, run `scripts/ldraw-part-facts.mjs`, which composes the official LDraw file's subfile transforms in LDU down to stud primitives. Against 23 hand-authored parts it found `34103`'s two studs at plus and minus 10 LDU, not 20, which is what "Offset" in its name means. Two traps are permanent: underside tubes are built from stud primitives too, so a 2x4 brick reports eleven studs until top and bottom are separated, and the library rate-limits bursts of subfile requests, so a non-404 is never reported as "no such part".
- `structuralDocumentValue` hashes `truth` with the parts, so a `BUILTIN_CATALOG_VERSION` bump moves every pinned baseline even when no placement changed; three booklet prefixes moved on a change that touched one part's body boxes and no connector. Before calling moved hashes a regression, restore the truth digests the bump moved (`truth.catalog.version`, `truth.catalog.hash`, `truth.collisionModel.hash`), change nothing else and re-hash: reproducing the old value bit for bit proves no part, colour, transform, step or connection moved. The same works on any pinned digest with a version folded in.

## Probes and measurement

- Before work whose only honest verdict is far away (reading instructions, generation quality, a rebuilt model), build the measurable intermediate and drive it. A booklet checks itself (step numbers run 1..N; callouts reconcile with the piece count), and a rebuild is scored per step by `compareBuilds` against the reference, not by hash equality. Record the number in `output/` and move it deliberately; a change with no number attached is not progress (2026-07-31: the step-64 parser bug surfaced only because sequence coverage was being measured).
- A test that reads ignored run evidence is gated on `LEGO_RUN_EVIDENCE=1` through `describeWithRunEvidence` or `itWithRunEvidence` (`scripts/run-evidence-gate.mjs`) or `requires_run_evidence` (`scripts/run_evidence_gate.py`), never on the path's existence, because an existence gate makes the default run depend on whatever a machine's ignored files hold: several tests ran on this machine and skipped on a clean clone. Opted in, a missing input fails by name. `scripts/run-evidence-gate-coverage.test.mjs` enforces this for Vitest and Python; the Playwright specs gated on `hasSampleBooklet` are not moved yet.
- Scoring runs (`*.score.test.ts`) run under `npm run test:score`, not `npm test`, because they measure the real booklet or a grown assembly, and the placement-branching curve alone took 100-134 s, past its own 120 s budget on a loaded machine.
- Quote identification accuracy only from the judged-callout line of `node scripts/identify-booklet.mjs`, because its other lines are not independent: the capacity constraint forces the inventory reconciliation, first-choice agreement compares two of the module's own stages, and callouts sharing a judged callout's drawing key agree with it by construction.
- A probe resolves its own dependencies and sample data rather than spelling out a repository path: four booklet probes built vite `/@fs/` URLs from a hardcoded `C:/Users/.../github/lego`, which from a worktree fell outside `fs.allow`, and all died on "Failed to fetch dynamically imported module". A worktree has no `node_modules` or `recipes/` of its own, so resolve builds with `require.resolve` and find `recipes/` by walking up, as `servableRoots()` in `apps/web/e2e/global-setup.ts` does for `server.fs.allow`.
- Smoothing a cost curve destroys its extremum, which is its sharpest point: at the true 48 px stud pitch the repeat cost was exactly `0.00` with both neighbours at `0.71`, because a second difference cancels at the right period, and a three-point mean added against raster noise made 48 px a local maximum (`47=0.43 48=0.47 49=0.43`) and moved the estimate to 45 px. There is no gate: `findPitchCandidates` is gone and the estimator now maximises a comb power, so no smoothing is left to reintroduce.
