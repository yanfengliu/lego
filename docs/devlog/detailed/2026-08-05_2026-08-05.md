## The first-fifty verdicts were keyed to a cluster index that renumbers, so all 87 were silently dead

**Timestamp:** 2026-08-05

**Action:** Re-keyed every hand-read verdict from cluster index to the SHA-256 of the crop actually put in front of the judge, plus the element it was claimed to be. Moved the lead-crop rule into one module that both the sheet generator and the scorer import, so the crop a verdict is keyed to cannot drift from the crop that was drawn. Added `verdictsUnbindable` to `firstFiftyAccuracy`.

**Code reviewer comments:** None recorded — the failure was found by running against the live closure, not by review.

**Result:** A cluster index is a position in a list that `match` rebuilds on every re-cut of the callout gallery, so one re-cut renumbered all 87 verdicts at once: against the live 863-callout / 273-cluster closure they scored `calloutsJudged` 0 while 187 callouts sat in range. The labels were intact; the key was dead. After the change: 84 pairs, 84 distinct digests, exactly 187 callouts and 320 pieces; `verdictsUnbindable` reads 87 instead of a plausible-looking 0/0.

**Reasoning:** Keying each callout to its own digest would have judged only 84 of 187, because a verdict is about a drawing while `calloutsInRange` counts callouts. A crop digest plus the claim invalidates in both directions and for the right reasons: change the picture and the verdict stops binding because nobody judged the new picture; change the claim and it stops binding because a different claim is unjudged rather than inherited. Renumbering, re-ordering, re-clustering and renaming all leave it alone, because none of them changes the bytes.

**Validation:** Seven regressions, including the renumbering that caused this. One bug surfaced by running rather than by testing: the assignment can leave a drawing claimed as nothing, and the old string key quietly became `"null:null"` and never matched. A strict key throws, forcing the caller to state what an unclaimed drawing means — unjudged, because its pair had no right-hand side.

**Notes:** The whole class of failure here is that a dead key reports 0/0, which is indistinguishable from nobody having labelled anything. That is why `verdictsUnbindable` had to be added at the same time as the fix.
