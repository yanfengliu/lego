# Devlog — 2026-09-02

## Every lesson deleted from `lessons.md` had its gate made to go red first

**Timestamp:** 2026-09-02 08:55 PDT

**Action:** Triaged all 66 rules in `docs/learning/lessons.md` against the fleet rule that a lesson ships with the gate that prevents its recurrence and the prose is then deleted. Each candidate lesson was mutation-tested: the smallest edit to product code that reintroduces the defect, the named gate run alone, the failure line captured, the file restored byte for byte, and the gate re-run green. `docs/learning/gate-proofs.md` records all of it and stays.

**Measured result:** 23 lessons had a gate that went red and were deleted with their evidence. 9 with no mechanical trigger and no repo specificity are staged in `docs/learning/canon-candidates.md` for the fleet constitution; 6 repo-specific ones moved to `docs/policies/local-rules.md`; 1 was already promoted into `AGENTS.md`. 27 rules remain, unproved and deliberately retained. `npm run lessons:check` passes on 27 paired halves.

**Two gates were fiction and are now real.** An anchor naming a real, passing test is not proof the test gates the lesson.

- "Err on the safe side has a direction." Its anchor names "seats a stud in the cavity, and refuses one a single LDU off the lattice" in `validation.test.ts`. That case stacks 1x1 bricks, which have no underside tube at all, and is about the cavity wall. Replacing the inscribed tube box `outerRadiusLdu / Math.SQRT2` with the bounding box `outerRadiusLdu` left it green; across all of `packages/brick-kernel` it moved only catalog hash pins, which report a changed digest rather than a refused build. New gate `packages/brick-kernel/src/tube-clearance.test.ts` measures the clearance from the lattice — a box of half-side h stands `(10 - h) * sqrt(2)` from a stud half a pitch away in both plan axes, against the stud's own 6 LDU — and stacks three real 2-wide parts. Under the bounding box it reports `-3.172 LDU` and reproduces the `PART_STUD_BODY_COLLISION` the lesson was written about.
- "Simulate bricks in centimetres, and give the ground real depth." Its anchor names the landing test in `rapier-world.test.ts`, which holds neither claim. Two independent defences now cover the tunnelling — a 100 cm slab and continuous collision detection — so `GROUND_SLAB_HALF_DEPTH_CM` → 0.001 is green, `enableCcd(false)` is green, and nothing anywhere looks at the unit system. New gate `apps/web/src/physics/rapier-world-scale.test.ts` derives the requirement from the drop instead: at `sqrt(2 g h)` for an 8 cm fall the body travels 2.09 cm in one 1/60 s step, so the slab has to be thicker than that. Metres and a 20-micrometre sheet each fail it by name.

**Four more gates were mutation-tested and stayed green; their prose was retained rather than deleted.** `EMERGENCE_WEIGHT` in `exploded-score.ts` can be zeroed with `exploded-score.test.ts` fully green. Moving the axonometric test back below the coarseness tie-break in `fitStudLattice`'s sort leaves all 22 cases of `camera-fit-lattice.test.ts` green — the printed-step-4 case that pins it is a Playwright spec needing the sample booklet. `ROTATION_ICON_SIDE_PT` can move 44.937 → 30 with `real-build-transition-classification.test.ts` green. And `run-ledger-file.ts` splits its five identity failures into five messages that name their observed values, but no test asserts any of them: the anchor's 46 failing tests failed on the device mismatch, not on the message.

**Baseline honesty.** The working tree carried 188 modified and 491 untracked files of unrelated in-flight catalog `/30` work, and `npx vitest run` was already red on it: 41 files / 103 tests on one run and 40 / 101 on another. None of it was stashed, reverted or `git checkout --`-ed; every mutation backed its file up in memory and restored it byte for byte. No proof uses the full suite as its red/green signal — each names one test file, run alone and seen green immediately after the revert.
