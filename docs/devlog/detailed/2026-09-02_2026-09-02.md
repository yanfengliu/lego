# Devlog — 2026-09-02

## Every lesson deleted from `lessons.md` had its gate made to go red first

**Timestamp:** 2026-09-02 08:55 PDT

**Action:** Triaged all 66 rules in `docs/learning/lessons.md` against the fleet rule that a lesson ships with the gate that prevents its recurrence and the prose is then deleted. Each candidate lesson was mutation-tested: the smallest edit to product code that reintroduces the defect, the named gate run alone, the failure line captured, the file restored byte for byte, and the gate re-run green. `docs/learning/gate-proofs.md` records all of it and stays.

**Measured result:** 23 lessons had a gate that went red and were deleted with their evidence. 9 with no mechanical trigger and no repo specificity are staged in `docs/learning/canon-candidates.md` for the fleet constitution; 6 repo-specific ones moved to `docs/policies/local-rules.md`; 1 was already promoted into `AGENTS.md`. 27 rules remain, unproved and deliberately retained. `npm run lessons:check` passes on 27 paired halves.

**Two gates were fiction and are now real.** An anchor naming a real, passing test is not proof the test gates the lesson.

- "Err on the safe side has a direction." Its anchor names "seats a stud in the cavity, and refuses one a single LDU off the lattice" in `validation.test.ts`. That case stacks 1x1 bricks, which have no underside tube at all, and is about the cavity wall. Replacing the inscribed tube box `outerRadiusLdu / Math.SQRT2` with the bounding box `outerRadiusLdu` left it green; across all of `packages/brick-kernel` it moved only catalog hash pins, which report a changed digest rather than a refused build. New gate `packages/brick-kernel/src/tube-clearance.test.ts` measures the clearance from the lattice — a box of half-side h stands `(10 - h) * sqrt(2)` from a stud half a pitch away in both plan axes, against the stud's own 6 LDU — and stacks three real 2-wide parts. Under the bounding box it reports `-3.172 LDU` and reproduces the `PART_STUD_BODY_COLLISION` the lesson was written about.
- "Simulate bricks in centimetres, and give the ground real depth." Its anchor names the landing test in `rapier-world.test.ts`, which holds neither claim. Two independent defences now cover the tunnelling — a 100 cm slab and continuous collision detection — so `GROUND_SLAB_HALF_DEPTH_CM` → 0.001 is green, `enableCcd(false)` is green, and nothing anywhere looks at the unit system. New gate `apps/web/src/physics/rapier-world-scale.test.ts` derives the requirement from the drop instead: at `sqrt(2 g h)` for an 8 cm fall the body travels 2.09 cm in one 1/60 s step, so the slab has to be thicker than that. Metres and a 20-micrometre sheet each fail it by name.

**Four more gates were mutation-tested and stayed green; their prose was retained rather than deleted.** `EMERGENCE_WEIGHT` in `exploded-score.ts` can be zeroed with `exploded-score.test.ts` fully green. Moving the axonometric test back below the coarseness tie-break in `fitStudLattice`'s sort leaves all 22 cases of `camera-fit-lattice.test.ts` green — the printed-step-4 case that pins it is a Playwright spec needing the sample booklet. `ROTATION_ICON_SIDE_PT` can move 44.937 → 30 with `real-build-transition-classification.test.ts` green. And `run-ledger-file.ts` splits its five identity failures into five messages that name their observed values, but no test asserts any of them: the anchor's 46 failing tests failed on the device mismatch, not on the message.

**Baseline honesty.** The working tree carried 188 modified and 491 untracked files of unrelated in-flight catalog `/30` work, and `npx vitest run` was already red on it: 41 files / 103 tests on one run and 40 / 101 on another. None of it was stashed, reverted or `git checkout --`-ed; every mutation backed its file up in memory and restored it byte for byte. No proof uses the full suite as its red/green signal — each names one test file, run alone and seen green immediately after the revert.

## Second pass: the six gates the first pass could not make go red

**Timestamp:** 2026-09-02 14:20 PDT

**Action:** Worked the 27 retained lessons, starting with the six named in `gate-proofs.md` as mutation-tested and green. Five of the six are now gated and proved red; the sixth was already covered and its second clause was proved separately. Baseline for every proof was the same dirty tree, and each proof names one test file run alone.

**Measured result, one line each.**

- **The split ledger diagnostics.** `recoverEvents` refuses a run event stream for nine distinct reasons and nothing asserted any message. Four of those nine were themselves collapsed into one sentence — the pre-open check shared "Run event stream is not a regular file" between a missing file, a symlink, a non-file and an extra hard link — so that was split first, and the truncated-record and unterminated-stream refusals now name their observed byte counts. `apps/companion/src/run-ledger-recovery-diagnostics.test.ts` drives the five conditions reachable by damaging a closed ledger and asserts both the observed value in each message and that no two messages read alike. Collapsing all ten back to `"Ledger file exceeds its byte cap"` fails 6 of 9.
- **`lstat` versus `fstat` on `dev`.** `sameFile` is now exported and pinned directly. A control on this machine measured both calls reporting `dev 3603962542` for one file, so the platform divergence does not reproduce here and no end-to-end recovery can exercise the tolerance — which is exactly why the predicate is the gate. Dropping the dev-0 tolerance and dropping the inode comparison each go red on their own case.
- **The exploded-step blend.** Every candidate in `exploded-score.test.ts` is handed one rectangle as both its emerged and its changed mask, so both readings return the same number and any weight scores identically. `apps/web/src/assembly/exploded-score-blend.test.ts` builds two steps where the readings disagree — a candidate the difference reading alone prefers and one the emerged region alone prefers — and the true placement wins only on the blend. `EMERGENCE_WEIGHT` at 0, 1, 0.45 and 0.56 all go red, so the weight is pinned to about (0.4545, 0.5455).
- **The rotation icon.** Every existing check builds its fixture from `ROTATION_ICON_SIDE_PT`, so moving the constant moved both sides of the comparison. `apps/web/test/real-build-rotation-icon-detection.test.ts` writes the 44.937pt side, the 0.5pt tolerance and the admitted band as literals; 44.937 → 30 fails 5 of 6. The lesson's second clause — that the icon has to be consumed — is held by `panel-face.test.ts`, and removing the toggle from `derivePanelFaces` fails 4 of 17 including the case that one missed icon inverts every later step.
- **The lattice selector.** The comparator was inline in `fitStudLattice` and reachable only through a raster. It is now `chooseLatticeCandidate`, behaviour-identical, and `packages/rendering/src/camera-fit-lattice-selection.test.ts` asserts the property rather than the instance: over every permutation of a candidate family, the chosen candidate passes the acceptance test whenever any candidate does. Moving the axonometric test back below coarseness picks printed step 4's index-2 sublattice at 9.11px of residual; all 22 cases of `camera-fit-lattice.test.ts` stay green under the same mutation.
- **The phase of a repeat.** The fold-versus-Fourier choice lives at every call site, and both readings are two numbers in cycles, so the site functions accepted either. They now take `LatticeSitePhase`, a marker only `foldedStudShape` returns, and `packages/rendering/src/camera-fit-lattice-site-phase.test.ts` proves the compiler refuses the other. Widening the parameters back fails `tsc --noEmit` with `TS2578: Unused '@ts-expect-error' directive` twice. Measured while writing it: on a synthetic grid the two phases agree to 0.0003 of a cell and the residuals from either are 0.2504px against 0.2501px, so no fixture this module can draw separates them — the type is the only gate available.
- **The red-pixel overcount**, the second clause of the exploded-step lesson, is held by `panel-arrows.test.ts`: disabling the origin check, the area cap and the fill cap each go red on their own case. A weak mutation is recorded beside them — a fill cap of 1 rather than `Infinity` leaves the file green, because a 99x30 plate fills 104% of the box measured from its own principal axis.
