# Canon candidates

Lessons this repository paid for that have no mechanical trigger and are not specific to it. They belong in the fleet constitution, not in a test and not in a local rule.

The parent promotes these into `fleet/FLEET.md` and then deletes this file. Until then it is the only copy, so each entry keeps its own anchor: a canon rule needs its provenance as much as a lesson does.

## A blocker you inherited is a claim, not a fact: retest it before repeating it, because its whole effect is to stop work.

**From:** lego / "A blocker you inherited is a claim, not a fact: retest it before repeating it, because its whole effect is to stop work."
**Why it has no gate:** it governs what a session does with a handoff note, and no test can run against a sentence in a document.
**Anchor:** commits `a6ebde8` through `88af17d` on 2026-08-04. A handoff recorded that Git writes were unavailable — an exact 15-path `git add` had hit a `.git/index.lock` permission error, escalation rejected by an approval-service quota said to last four more days. The next session believed it and planned around it; roughly four thousand lines of approved work sat unprotected in the working tree across two sessions. One command disproved it: `.git` was writable, no stale lock existed, `git add` returned 0, and the first `git push` succeeded. 144 paths were then committed in fourteen pathspec commits. The same session found the identical shape a second time in the same handoff — "the only registered Python is 3.14.0", disproved by one `where python`. The rule is not "distrust handoffs": a handoff recording a real failure is doing its job. It is that a *blocker* is the one kind of inherited claim that must be retested, because its entire effect is to stop work and it costs one command against days of not shipping.

## A pipeline exits with its last command's status, so `npm run x | tail` reports tail's success over any failure; capture the command's own code.

**From:** lego / "A pipeline exits with its LAST command's status, so `npm run x | tail` reports tail's success over any failure; capture the command's own code."
**Why it has no gate:** it is a property of how an agent invokes a shell, not of any code in any repository.
**Anchor:** 2026-08-09, three separate occurrences in one session. `npm run verify 2>&1 | tail -40` was read as exit 0 when verify had failed with 978 lint errors. `node scripts/part-identification.mjs ask ... | tail` was read as success when the pass had died at 102 of 269 answers. And a backgrounded compound command's completion code was read as the command's when it belonged to the `tail` that ended it. Each time the report was "green" and the underlying work had failed. The fix is mechanical — `cmd > log 2>&1; echo "EXIT=$?"` — and it kept recurring because the wrong answer looks exactly like the right one. `npx vitest run -t "<name>"` is the same trap from another direction: it exits 0 when the filter matches nothing, so a filtered green run can mean the assertion never executed.

## A gate that cannot distinguish "passed" from "did not run" will report the second as the first, so prove it fails before trusting that it passes.

**From:** lego / "A gate that cannot distinguish 'passed' from 'did not run' will report the second as the first, so prove it fails before trusting that it passes."
**Why it has no gate:** it is the rule that makes gates trustworthy, so nothing below it can hold it up. It may already be covered by the canon line "a gate is only real once mutation-proved against the specific defect" — promote it as a strengthening of that rule rather than a second one if so.
**Anchor:** 2026-08-09, commits `90a4a87` and `a44b53a`, after eight instances surfaced in two days. `real-build-builder-calibration.test.ts` resolved its inputs through `process.cwd()` and skipped mutely when they were absent, so the strongest assertion this repository makes about Builder frame truth did nothing from any subdirectory and reported `6 passed, 1 skipped`, exit 0. Its companion was vacuous the same way. `real-build-official.test.ts` had it too, silencing the case that pins the official model's sha256 and its 1,465 bricks. `real-build-transition-bundle.test.ts` was worse: its mirror case PASSED while asserting the artifact was absent, with the file present at 34,784 bytes. The same shape without a skip: `real-build-action-ledger.spec.ts` asserted `identificationConfidence` equalled `"vision-kept"`, written 53 minutes before the code stopped hard-coding that literal into every piece, so it checked a constant against itself until a refactor silently turned the tautology into a gate. Every one of them was green. The failure mode IS the success signal, so the only way to see it is to make the gate fail on purpose and watch it name the reason.

## A check built from the same symbol as the thing it checks proves only that the code agrees with itself; verify a destination by naming it independently.

**From:** lego / "A check that reads the same constant as the code it checks cannot see that the constant is wrong; look at the destination from outside."
**Why it has no gate:** it is a property of how a check is constructed, and any gate written for it would be an instance of the fault it names.
**Anchor:** 2026-08-05, set 6651557. A new publisher needed an opt-in flag and `LEGO_REAL_BUILD_TRANSITIONS=1` was the obvious name. That variable already existed: `real-build-input-files.ts` uses it to override the *path* the transition-classification input is read from. Setting it to `1` made the path `1`, so three consecutive green runs wrote 34,784 bytes to `<repo>/1` while `output/real-build/transition-classifications.json` never existed. Three assertions ran immediately after the write and all three passed — the returned path ended with `TRANSITION_CLASSIFICATIONS_PATH`, `existsSync` was true, and the bytes read back equalled the bytes written — because every one was computed from the same poisoned constant. `"C:/…/lego/1".endsWith("1")` is true. The only thing that noticed was `ls` in the directory the file was supposed to be in. Two rules: grep an environment variable name before adding one, because a repository that reads configuration from the environment has a namespace; and verify a destination by naming it independently — an absolute literal, a directory listing, or a second process.

## A measurement belongs where the thing it measures becomes available, not where the caller wants it: computed after an early return it reports zero, and zero reads as an absence.

**From:** lego / "A measurement computed after an early return reports zero, and zero reads as an absence."
**Why it has no gate:** the fault is where a statement sits relative to a `return`, and it is invisible to any check that does not already know what the number should be.
**Anchor:** three times in one session, in `apps/web/e2e/real-panel-scoring.ts`. A step that printed a perfectly good arrow and then failed for want of a fitted camera returned through a blank-report helper that hardcoded zeros, so the census of "how many steps print an arrow" answered "how many steps got all the way through" instead. The same fault hid the on-model test and the clearance measurement. It does not look like a bug from the code: every field is populated, every value is plausible, nothing throws. It is only visible against the world — the panels plainly had arrows on them — which is why it survived a careful read of the diff and died the moment the pictures were opened. Arrows on the model went from 3 to 11 when the measurements moved above the skips, and 3 would have been small enough to abandon the approach. A report that cannot distinguish "measured zero" from "never measured" should be returning null.

## A shape test has to be validated against the art it will meet, not against a synthetic instance of the thing it rejects: "it passes" and "it fires" are different claims.

**From:** lego / "A shape test that works on a solid blob need not work on printed art; 'it passes' and 'it fires' are different claims."
**Why it has no gate:** the repository's own gate for it is the counterexample. `panel-arrows.test.ts` proves the fill test refuses a solid 99x30 rectangle, which is exactly the synthetic instance the lesson warns against; the printed 2x6 plates that motivated it are sparse figures that came through under the same threshold.
**Anchor:** a red arrow is the booklet's only statement of where a part travels, and the set has red parts too. A 2x6 plate seen in axonometric is three times longer than it is wide, which clears an elongation gate meant to catch blobs, and on a panel drawn at 21 pixels per stud it is under an area cap sized for a panel drawn at 42. Steps 12 and 16 of the sample booklet each let one through, and each produced a diagonal displacement — which matters more than the count, because they are the *only* two diagonal displacements in the first fifty steps. The obvious third test is how much of its own oriented box the shape fills: an arrow fills about a third, a plate fills most of it. It is right about a plate and wrong about a *drawn* plate. Instruction art rings every stud and shades every face, so the saturated red of a printed brick is a sparse figure, not a filled rectangle. The test was written, unit-tested against a solid rectangle, passed, and changed nothing on the corpus it was written for: zero of step 12's 10 rejected red regions and zero of step 16's 31 mention fill. `maxFillFraction` in `apps/web/src/assembly/panel-arrows.ts` carries that note at its declaration.

## The shape of the question decides what a model call is worth: a closed question two raters can be compared on is auditable where an open one is not.

**From:** lego / "Closed questions are easier to audit: two blind raters agreed on 84/84 pairs; open pick-one-of-six was 39.9% self-consistent. Agreement is not correctness."
**Why it has no gate:** it is how to pose a question to a model, decided before any code exists to test.
**Anchor:** two configurations, the same booklet, the same model family, the same day. Asked an open N-way question — a card of candidates beside the callout, answer with a pick number, free text and a confidence — the Claude Opus 5 closure retains 273 answers of 285 drawings and agrees with itself on 138 of 265 checkable descriptions, 52.1 percent. Confidence is only a weak separator, `0.892061` mean on kept answers against `0.877480` on contradicted ones, so it cannot be an admission gate. Asked a closed binary question — two pictures side by side at the same height, is this the same part, nothing else on screen — two independent raters on different models agreed 84 of 84, including all eight "different" calls and both unjudgeable pairs. What moved it: the answer space was small and checkable; the answer was withheld, so the judge could not be led by a name or an element id; uncertainty had somewhere to go, and "unsure" was used exactly twice, both times correctly; and escalation was built in, contact sheets first and single-pair renders for anything ambiguous. Agreement is not correctness — the result supports the framing and the auditability of the question, not the truth of every shared verdict. The corollary is that a disappointing vision result is not automatically a model limit: check first whether it was asked something answerable, and whether the grader is measuring sight or vocabulary.

## Reading a thing in isolation is a different problem from reading it out of a scene, and the picture is worth more than the prompt.

**From:** lego / "Reading a part from an isolated thumbnail is a different problem from reading it out of an assembly."
**Why it has no gate:** it is a fact about which measurement to attempt, established before a pipeline is built.
**Anchor:** `output/vision-benchmark.json`; labels are element ids paired from the text layer by `apps/web/src/instructions/parts-inventory.ts`, resolved against Brickset's published inventory for set 21066. The same model, asked what part a step adds, answered 6 of 6 assembly crops at 0.35–0.58 self-reported confidence and got at least one plainly wrong. Asked the same question about the booklet's own inventory thumbnails — one part, isolated, on a plain ground — it scored 28/28 on stud dimensions, and the naive control prompt still scored 27/28. The prompt was worth about 4 points; the picture was worth the rest. Every surviving miss was a taxonomy artifact, where the answer vocabulary had no entry for an arch or a modified brick, rather than a misreading of the shape.

## The true extremum of a cost curve is its sharpest point, so smoothing to suppress noise is the first thing that destroys it.

**From:** lego / "A cost curve's true minimum is its sharpest point; smoothing to suppress noise turns it into a local maximum."
**Why it has no gate:** the module it was found in has since been rewritten. `findPitchCandidates` no longer exists and the estimator maximises a comb power rather than minimising a cost, so there is no smoothing left to reintroduce and nothing to make go red.
**Anchor:** the stud-pitch estimator scored each candidate period by how badly the traced edge failed to repeat at it, then looked for the dip. At the true period of 48 px the cost was exactly `0.00` while both neighbours sat at `0.71`, because a second difference cancels perfectly when the period is right. A three-point mean, added to stop raster noise passing for a dip, averaged that zero against its neighbours and made 48 px a local *maximum*: smoothed the same three samples read `47=0.43 48=0.47 49=0.43` and the estimate went to 45 px, on the shoulder. The dip that matters is one sample wide by construction, so it is the first thing any smoothing removes.

## A guard test that passes for an incidental reason is a false green: make it fail on purpose before believing it, and remove the accident rather than the assertion.

**From:** lego / "File metadata cannot see a same-size rewrite, and a guard test that passes on an incidental clock tick is a false green." — the metadata half is now gated; this half is the transferring one.
**Why it has no gate:** it is a property of how a test came to be green, and any check written for it would have to know what the test meant to prove.
**Anchor:** `sameFileState` compared `dev`, `ino`, `size`, `mtimeNs` and `ctimeNs` across a bounded read. On NTFS the default clock granularity is about 15.6 ms, so two same-size writes inside one tick are byte-identical in metadata — measured at 72.5–79.0% of 200 samples. The guard test passed anyway, and it passed because an `await import(...)` sat between the write and the check, letting the clock tick. Replayed without that incidental delay, 30 to 33 of 50 mutations went undetected. The test was not weak in a way anyone could see; it was strong because of a line that had nothing to do with the property. The same shape has now been measured three ways in this fleet: a cache test that went red only by accident of an empty-bytes fixture, a gate that was red on 2 of 3 runs, and this one. The remedy is the same each time — reintroduce the defect deliberately and watch the gate fail — and the second half of it is to delete the accident, not to weaken the assertion.

## A test that proves a safety property has said nothing about correctness, and a green safety run must not be reported as one.

**From:** lego / "A green vision narrowing can drop settled truth; staying inside the enumerator is safety, not visual correctness."
**Why it has no gate:** it governs what a passing run is allowed to be reported as, and the run itself is green either way.
**Anchor:** 2026-08-10, `recipes/6651557.pdf` page 11, retained run `2026-08-09T06-52-45-853Z-622f66a3fe8d`. A model reading of printed step 4 saw the correct underside viewpoint and then described both pieces as beside one another with zero overlap. Replayed against the retained enumeration, the 1x8 plate narrowed 480 candidates to 12 and dropped its settled transform; the wedge kept all 190 and dropped its settled transform because its anchor was not yet placed, making the product unusable. The oracle reading kept the settled wedge while narrowing 190 to 2. The focused replay stayed 6/6 green throughout, because it proves exactly what it was written to prove: every survivor came from the enumerator, and an unusable reading cannot invent a placement. That boundary says nothing about whether the description retained the real answer. Report truth loss separately from subset safety, refuse known disagreements, and never let one stand in for the other.
